# 维护者发布核对清单

本清单用于维护者检查源码、文档、隐私和版本一致性；普通使用者可直接按README安装和运行。

## 仓库信息

- 项目名称：`dicom-inventory`。
- 描述：只读、离线的DICOM元数据质量审阅工具，支持分层检查、人工审计和有依据的复检对比。
- 仓库简介参考：离线只读的DICOM元数据清点与质量审阅工具，支持Study/Series分层检查、人工问题跟踪、复检对比与CSV导出。
- 标签参考：`dicom`、`medical-imaging`、`data-quality`、`pydicom`、`pyside6`、`desktop-app`。

仓库可见性、访问权限和许可证按维护策略管理。项目暂未提供LICENSE，文档不能将其表述为已按某种开源许可证授权；第三方代码、图标和依赖的来源与许可需单独核对。

## 源码包核对

运行`python -m tools.build_source_bundle --output dist`按白名单生成源码ZIP。已有同名包追加编号，不覆盖原包。`DELIVERY_MANIFEST.json`记录各文件路径、大小和SHA-256。

白名单包括应用代码、测试、tools、README、依赖与pytest配置、用户操作手册/技术参考等指定文档和六张合成截图；仅在项目已有LICENSE时收录该文件。

- [ ] 核对包内文件与当前源码及清单一致，压缩文件可正常解包。
- [ ] 确认没有真实DICOM、患者身份、私人路径、密钥、工作备注、CSV、SQLite、虚拟环境或个人工程记录。
- [ ] 逐张检查截图，只使用合成演示，核对画面中的路径、UID和备注。
- [ ] 在干净目录验证依赖安装、合成样例生成和软件启动。
- [ ] 核对README图片、相对链接、版本说明、测试记录及功能边界。

`.gitignore`不是匿名化工具，也不会自动移除已经跟踪的文件。白名单和密钥模式检查不能替代人工内容审阅。

## 仓库与版本一致性

- [ ] 确认账号、仓库名、可见性、访问权限和许可信息。
- [ ] 提交前核对待提交列表及差异，不包含本地运行数据。
- [ ] 仓库根目录包含README、dicom_inventory、tests、tools、docs和依赖配置，而不只是一个ZIP。
- [ ] 从新的克隆目录生成合成演示并启动软件，核对文档与实际操作一致。
- [ ] 对外版本的说明、源码和校验文件相互对应；打包exe或创建Release时另行验证。

演示数据、工作数据库和导出文件保存在独立输出目录，不作为仓库内容。
